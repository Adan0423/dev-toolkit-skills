# Web Design Suite

Entrada de diseño con procedimientos selectivos. Identifica audiencia, tarea, identidad
y límites desde contexto del usuario, proyecto y material disponible. Pregunta solo
lo decisivo que falte; no obliga a una entrevista nueva para ajustar un botón.
No requiere slash commands de Impeccable ni otra skill instalada.

| Trabajo principal | Guía |
|---|---|
| Crear dirección visual o página con identidad | [direction](references/specialties/direction/guide.md) |
| Elegir bibliotecas/sistema UI tras analizar el proyecto | [stack](references/specialties/stack/guide.md) |
| Definir brief/UX antes de un diseño amplio | [discovery](references/specialties/discovery/guide.md) |
| Auditoría técnica de accesibilidad, responsive y temas | [audit](references/specialties/audit/guide.md) |
| Corregir móvil, tablet, orientación o anchos intermedios | [responsive](references/specialties/responsive/guide.md) |
| Layout, espaciado, jerarquía y distribución | [layout](references/specialties/layout/guide.md) |
| Tipografía y legibilidad | [typography](references/specialties/typography/guide.md) |
| Paleta, contraste y aplicación de color | [color](references/specialties/color/guide.md) |
| Animación y microinteracciones | [motion](references/specialties/motion/guide.md) |
| Acabado visual final | [polish](references/specialties/polish/guide.md) |
| Lentitud/lag y coste de renderizado UI | [performance](references/specialties/performance/guide.md) |
| Evaluación UX y crítica del diseño | [critique](references/specialties/critique/guide.md) |

Lee una guía para la tarea dominante. No lee todas ni activa otra por nombrarla en un
texto. Audit produce evidencia técnica; critique evalúa UX; polish corrige detalles.
Stack solo si elegir/cambiar tecnología forma parte del problema. Para rediseño amplio
puedes pasar de direction a responsive/polish cuando ese trabajo concreto empiece.

## Contrato de todas las especialidades

Guías internas con rutas relativas propias, sin registro automático de sub-skills.
Las preparaciones específicas complementan el contexto, no obligan a recargar toda
la familia. Preserva diseño/lógica pedidos: una mejora de espaciado no autoriza cambiar
rutas, backend, permisos o marca. Moderno no exige un efecto o tipografía universales.
Trabaja con datos y estados reales; no simula pagos/formularios exitosos ni fabrica reseñas.

Reutiliza componentes/tokens del proyecto. Prueba móvil/tablet/desktop e intermedios,
zoom, teclado, estados y contraste afectados. Dark mode si existe o está solicitado:
superficies/controles completos y reduced-motion. No declara responsive completo por
un preset. Entrega cambios, guía usada, evidencia y partes no verificadas.
