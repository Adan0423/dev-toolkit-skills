# WordPress Suite

Inspecciona WordPress/PHP, modalidad/hosting, tema, editor, plugins, licencias y acceso.
Confirma sitio/entorno. Trabaja en español salvo otra necesidad. No convierte sitios
entre Elementor y código propio para simplificar una intervención local.

| Contexto principal | Procedimiento |
|---|---|
| Crear/extender tema propio, clásico, de bloques o hijo | [code](references/specialties/code/guide.md) |
| Sitio Elementor, WooCommerce o diseño mediante plugins | [builder](references/specialties/builder/guide.md) |

Lee una guía solo si el trabajo es de diseño/tema. Si es solo contenido o configuración,
salta directamente a una referencia del contexto real:

- WordPress nativo: [contenido y ajustes](references/specialties/code/references/content-operations.md).
- Elementor/WooCommerce: [artículos/medios](references/specialties/builder/references/content.md)
  o [productos/comercio](references/specialties/builder/references/woocommerce.md).
- Acceso nativo: [MCP/REST/CLI](references/specialties/code/references/connections.md).
- Acceso builder/plugins: [MCP y plugins](references/specialties/builder/references/connections-plugins.md).

No lee las dos ramas ni carga todas las referencias. Si no sabes editor pero solo piden
un artículo, empieza con contenido nativo sin modificar diseño. Si piden tema con código
puro selecciona code; si solo arreglar Elementor selecciona builder. Las especialidades
son guías internas, sin exigir instalar sus skills originales ni registro anidado.

Conserva modelo de contenido, SEO, rutas, roles y compra. Diseño editable, responsive
móvil/tablet/desktop y claro/oscuro/sistema con pruebas. MCP se descubre por capacidades
reales; su ausencia no bloquea preparar trabajo revisable. Revalida plan/versiones.
Cargar contenido sin estado explícito: drafts; publicar cuando pedido. Diseño no autoriza
cambiar pagos/envíos/impuestos ni cobros de QA. Entrega IDs/URLs, pruebas, guía y pendientes.
