# Harvard Resume Format
 
Source: Harvard FAS Office of Career Services, "OCS Resumes & Cover Letters" (Undergraduate Resource Series, © President and Fellows of Harvard College). This skill distills their public guidance into a reusable structure and rule set — it is not an official Harvard product.
 
## When to use this
 
- User explicitly asks for a CV/resume in "formato/modelo Harvard".
- User wants a resume made more concise, scannable, or "professional".
- User wants a critique/audit of an existing resume's structure or language.
- Building a CV from scratch and no other format is specified — this is a strong, safe default.
## Core structure (in this order)
 
1. **Header** — Full name (largest text), then a single line: address (optional/city) • email • phone • LinkedIn/portfolio. No photo, no age, no gender, no marital status.
2. **Education** — Reverse chronological. Institution name (bold/caps) + City on one line, right-aligned or same line; degree/concentration + graduation date (or "en trámite de titulación") on the next. GPA/honors only if strong or requested. Relevant coursework only if directly relevant to the target role.
3. **Experience** — Reverse chronological. Organization + City on one line; Title + Month Year – Month Year on the next. 2–4 bullets per role, each starting with a strong action verb (see `references/action_verbs.md`), no personal pronouns, quantify results wherever possible ("reduced X by Y%", "supported N users").
4. **Leadership / Activities / Projects** (optional, rename to fit) — Same format as Experience. Include when it strengthens the pitch for the target role, especially for candidates with limited formal work experience — reorder above Experience if it's more relevant.
5. **Skills & Interests** (optional) — Grouped lines: `Technical:`, `Language:`, `Laboratory:` (if applicable), `Interests:` (only if space allows and it could spark conversation). Never pad with skills the candidate doesn't actually have.
Choose **bulleted** or **paragraph** style for the Experience/Activities entries, and use it consistently throughout — never mix.
 
## Hard rules
 
**Language:**
- Specific, not general. Active, not passive. Fact-based — quantify and qualify.
- Written to be scanned quickly, not read as prose.
- No personal pronouns ("yo", "I"). Each bullet is a phrase, not a full sentence.
- No slang, no flowery/narrative language.
**Don't include:**
- A photo, age, or gender.
- "References available upon request."
- A line that starts with a date (dates go at the end of the line, not the start).
- Abbreviations that aren't universally understood in the target industry.
**Formatting:**
- One page, unless the user has 10+ years of relevant experience or the employer explicitly asks for more.
- Consistent font, size (10–12pt), and spacing throughout. Common, professional font.
- Consistent use of bold/italics/caps for emphasis — same pattern every time it recurs.
- Sections ordered by importance to the target role — not necessarily the order above if something else is more relevant (e.g., move Skills or Projects above Experience for a technical/junior candidate with a strong project portfolio).
- Within every section: reverse chronological (most recent first), and no unexplained gaps.
- Consistent presentation of numbers (all numerals or all words, not both) and of verb tense (past roles = past tense, current role = present tense).
- Must render correctly when exported to PDF — always deliver the final resume as a PDF, and check that fonts/spacing survive the conversion.
## Top mistakes to catch when reviewing a CV against this format
 
1. Spelling/grammar errors.
2. Missing email or phone.
3. Passive language instead of action verbs.
4. Poor organization — not easy to skim in ~10 seconds.
5. Achievements stated without results/impact.
6. Too long for the candidate's experience level.
7. Inconsistent narrative across multiple CV versions (different job titles, different employment dates, conflicting claims) — flag this explicitly if the user has multiple CV drafts, since recruiters cross-checking LinkedIn/portfolio against the CV will notice.
## Workflow for building or reformatting a CV with this skill
 
1. Gather the candidate's real, verified facts first (don't invent dates, titles, or metrics). If a portfolio database, LinkedIn, or multiple existing CV drafts are available, reconcile them and flag contradictions to the user before writing — don't silently pick one version.
2. Pick the target role/industry; reorder sections and select which experiences/bullets to surface accordingly.
3. Draft bullets: action verb + task + quantified result. Vary the verbs — see `references/action_verbs.md` for categorized options (Leadership, Communication, Research, Technical, Teaching, Quantitative, Creative, Helping, Organizational).
4. Lay it out per the structure above, one page, consistent formatting.
5. Render to PDF and visually check pagination/overflow before delivering (see docx/pdf skills for the actual file-generation mechanics — this skill governs content and layout rules, not the file format tooling).
